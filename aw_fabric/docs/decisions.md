# Decision log

Source of truth: [adventure_works.txt](source/adventure_works.txt) for the OLTP and [adventure_works_dw.txt](source/adventure_works_dw.txt) for the Gold shape. `AdventureWorksDW2025` is never loaded into Fabric. Gold row counts will not match that backup: this OLTP has 121,317 order lines, and the backup's two sales facts add up to 121,253.

| Decision | Options considered | Choice | Why | Trade-off |
|---|---|---|---|---|
| Ingestion | Mirroring, Copy job CDC, pipeline Copy, notebook JDBC, Dataflow Gen2 | Lookup + ForEach + one Copy activity through the existing gateway | It is the only path that can project columns, serialize geography, hierarchyid, and xml, skip blobs and `Person.Password`, and then chain Silver, DQ, and Gold. SQL Server 2025 mirroring needs Azure Arc, and this database already has CDC enabled, which blocks it. Spark cannot use the gateway. | A control query to maintain. No continuous replication. The backup is static, so that is acceptable. |
| CDC | Restore without CDC, disable CDC, enable table CDC, leave it | Leave database CDC enabled and capture no tables | The pipeline only runs `SELECT`. Empty CDC does not affect those queries. Restoring would drop the database user for no design benefit. | SQL Server 2025 mirroring stays unavailable on this database. |
| Incremental | CDC, watermark on every table, full overwrite | `RunMode` default `Full`. `Incremental` upserts only `Sales.SalesOrderHeader` and `Sales.SalesOrderDetail` | A full copy of this database is cheaper than watermark state. A watermark cannot see deletes. | Deletes in those two tables are invisible until the next full run. |
| What Gold models | Every OLTP table, the official DW including finance and call center, or the sales star | Sales star shaped by the DW, built from this OLTP | `FactFinance`, `FactCallCenter`, `FactSurveyResponse`, and the daily inventory fact cannot be built from this backup. Purchasing and work orders stay in Bronze. | The warehouse is not a model of the whole company. |
| Customer dimensions | One `DimCustomer`, or the DW split | `DimCustomer` where `StoreID` is null, and `DimReseller` from `Sales.Store` | That is the warehouse shape. Store count is 701 in both databases. | A person and a store are not one dimension. |
| Sales reason | Reason text on a header bridge, or `DimSalesReason` plus a line-grain factless fact | `DimSalesReason` and `FactInternetSalesReason` keyed by `(SalesOrderNumber, SalesOrderLineNumber, SalesReasonKey)` | The OLTP key is header grain, `(SalesOrderID, SalesReasonID)`, 27,647 rows. The warehouse stamps each reason onto every line. | Reason counts are higher than 27,647. They will not equal the backup's 64,515 rows. |
| Line number | Use `SalesOrderDetailID`, or a sequence inside the order | `ROW_NUMBER()` within `SalesOrderID` ordered by `SalesOrderDetailID` | The warehouse line number is a `tinyint`. `SalesOrderDetailID` is a table-wide `int`. | `SalesOrderDetailID` is kept as a hidden reconciliation column, not as the key. |
| Promotion | Factless coverage only, or a key on the line | `DimPromotion` from `Sales.SpecialOffer`, with `PromotionKey` on both line facts | `SalesOrderDetail.SpecialOfferID` is the offer applied to the line. Both databases have 16 offers. | `SpecialOfferProduct` is a Silver input for the foreign key, not a Gold fact. |
| Tax and freight | Header fact, or allocate onto lines | Allocate by the line's share of header `SubTotal` | The warehouse stores `TaxAmt` and `Freight` on the line. In this OLTP they exist only on `Sales.SalesOrderHeader`. | A zero subtotal keeps both amounts on the first line. The line sums must equal the header. |
| Null currency rate | Guess USD, or quarantine | Quarantine until a query shows those orders are USD | The metadata files do not prove the rule. | The Gold load does not guess. |
| Ship method | Omit it, as the sample warehouse does, or keep it | `DimShipMethod` | Every OLTP order has `ShipMethodID`. | One dimension the sample warehouse does not have. |
| Geography | One row per street address, or city / state / country | `DimGeography` at city, state, and country. Customer and reseller hold the key | That is the warehouse grain. This OLTP has 19,614 addresses. | Street address is not a Gold dimension. |
| Product | Snowflake subcategory and category, or one dimension | Names flattened onto `DimProduct` | The report should not need the snowflake. | Category is not its own dimension. |
| Silver scope | Clean all 69 tables, or only Gold inputs | Only Gold inputs, in schema `cleansed` | The other tables have no Gold consumer. Cleaning them spends a Spark session for no model. | Purchasing, work orders, and inventory stay raw in Bronze. |
| Layout | Partition, Z-order, liquid clustering, or none | None | Largest table is 121,317 rows. Partitioning would create small files. | Revisit liquid clustering only if the sales lines grow about 100x. |
| Spark | One notebook per table, or one notebook | One Runtime 2.0 notebook on the starter pool | Session startup is the expensive part on a trial. | A failure is isolated per table inside the notebook, not by a separate session. |
