# Decision log

Source of truth: [adventure_works.txt](source/adventure_works.txt). `AdventureWorksDW2025` is not loaded into Fabric. Shelf quantity in `ProductInventory` matches purchases plus work orders minus sales for 0 of 432 products. That check is why `FactStock` does not read `ProductInventory`.

| Decision | Options considered | Choice | Why | Trade-off |
|---|---|---|---|---|
| Ingestion | Mirroring, Copy job CDC, pipeline Copy, notebook JDBC, Dataflow Gen2 | Lookup + ForEach + one Copy activity through the existing gateway | It is the only path that can project columns, serialize geography, hierarchyid, and xml, and skip blobs and `Person.Password`. SQL Server 2025 mirroring needs Azure Arc, and CDC is already enabled. Spark cannot use the gateway. | A control query to maintain. No continuous replication. |
| CDC | Restore without CDC, disable CDC, enable table CDC, leave it | Leave database CDC enabled and capture no tables | The pipeline only runs `SELECT`. Restoring would drop the database user for no design benefit. | SQL Server 2025 mirroring stays unavailable on this database. |
| Incremental | CDC, watermark on every table, full overwrite | `RunMode` default `Full`. `Incremental` upserts only `Sales.SalesOrderHeader` and `Sales.SalesOrderDetail` | A full copy of this database is cheaper than watermark state. A watermark cannot see deletes. | Deletes in those two tables are invisible until the next full run. |
| Sales grain | Two facts split by `OnlineOrderFlag`, or one fact | One `FactSales` row per `SalesOrderDetail` | The KPIs are total quantity, total sales, average price, and top and bottom products. One fact serves all of them. | Promotion, sales reason, currency, employee, and quota are not in the star. |
| Customer and store | One customer dimension, or person and store apart | `DimCustomer` for a person and `DimStore` for a store | 18,484 customers are person-only, 701 are store-only, and 635 are both. A line can point at both. | Store-only lines use customer `-1`. Person-only lines use store `-1`. |
| Store address | Every address, or address type 3 | Address type 3, Main Office | All 701 stores have that address. Eleven also have Shipping. Using only type 3 keeps one row per store. | The shipping address is dropped. |
| Person address | One type, or a priority | Primary, then Home, then Billing, then Shipping. Tie-break `AddressID` | A person can have more than one address. The dimension needs one. | The other addresses are dropped. |
| Tax and freight | Leave them on the header, or allocate to the line | Allocate by the line's share of header `SubTotal` | The fact is line grain. A zero subtotal keeps both amounts on the first line. | The line sums must equal the header. |
| Stock balance | Shelf snapshot, rollback from `ProductInventory`, or purchases minus sales | `FactStock`: purchases minus sales, by product and day, starting at 0 | The shelf quantity does not match the movement total. `TransactionHistory` has no location. Work orders and parts issued are excluded. | Opening and closing are not the quantity on the shelf. `ProductInventory` stays in Bronze and is not a fact. |
| Stock location | `DimLocation` on `FactStock`, or no location | No location | `P` and `S` rows have no `LocationID`, shelf, or bin. | Plant, shelf, and bin cannot be sliced on `FactStock`. |
| Layout | Partition, Z-order, liquid clustering, or none | None | Largest sales table is 121,317 rows. | Revisit liquid clustering only if the sales lines grow about 100x. |
| Spark | One notebook per table, or one notebook | One Runtime 2.0 notebook on the starter pool | Session startup is the expensive part on a trial. | A failure is isolated per table inside the notebook. |
